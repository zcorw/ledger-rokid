# Flow Ledger for Rokid

**English** | [简体中文](README.zh-CN.md)

A receipt capture and recognition agent for Rokid AIUI, paired with Flow Ledger 2.

The development branch follows the owner's sketch: merchant, amount, date and account occupy four fixed rows with inline labels/values; category sits beside amount. Seven field labels remain visible even when values are empty. Voice edit, Draft and Confirm stay in one row at the bottom. Merchant text fills a definite width with a trailing gutter; long names wrap and scroll vertically inside that row. Other long values scroll horizontally within their own slots. Confirmed currency codes accompany symbols; an unknown currency is explicitly marked for review. Temple swipes select bottom actions and head motion selects fields; see [workflow and acceptance](docs/REVIEW-WORKFLOW.md) and [TODO.md](TODO.md). New-package device acceptance is separate from code completion.

- Opening the agent checks its saved binding first. An unbound device shows the phone binding URL and code before opening the camera. After approval, or with an existing saved binding, the live viewfinder opens automatically with the caption “单击拍照，自动识别账单”.
- One activation releases the preview camera, captures a high-quality photo in `default` mode to preserve the full field of view, and starts recognition automatically. The frozen photo stays visible during recognition. Compare preview and photo framing on the glasses; matching framing is not yet verified.
- First use requires signing in on the phone at the [device authorization page](https://ledger.zcorw.xyz/receipt-devices), entering the code shown on the glasses and explicitly approving it before capture. Receipt-only authorization remains valid until revoked or the account password changes. The credential is saved in Agent-isolated storage and restored after exit or device restart. Clearing Agent data requires authorization again.
- The original JPEG/PNG/WebP bytes are uploaded unchanged over HTTPS and privately archived with the recognition record on the VPS; only a separate server-side copy is converted for recognition. The backend calls its configured recognition service. Validated actual bill fields appear in the registered capture page's four-row review layout. Unconfirmed fields stay empty, including the amount; no sample values or placeholders are inserted. Expenses are not saved automatically.
- View archived originals at **Daily Expenses → Recognized receipts** on the website; saved expenses can link the same receipt. Existing photos that were never uploaded/stored cannot be recovered.
- **Draft** saves the current candidate against that same original, without another upload or expense. Repeated clicks reuse an operation key; uncertain responses are checked before retry. On the website, filter unposted drafts or search the merchant to continue editing. This requires backend migration `0014_receipt_drafts` and the matching website/backend deployment.
- **Confirm** requires a complete reviewed candidate and a separate phone acknowledgement enabling accounting for this exact device. Existing receipt grants are not upgraded automatically. The server reuses the existing expense writer and freezes the reviewed draft revision; duplicate clicks, retries and restart recovery cannot create another expense for the same receipt. A possible duplicate requires a second explicit confirmation. Local recovery stores only backend-bound receipt/revision/request IDs; it queries the outcome before any explicit retry, never stores bill fields or photos. The permission can be revoked independently on the phone. Successful confirmation offers **Continue capture**.
- Cancel, hide and exit stop the viewfinder, clear local photos and abort network work. This does not delete an original already stored by the server. Recognition failures can retry the same photo or take a new one.
- **Voice edit** starts continuous microphone recognition only after activation and shows live recognized text, including revisable interim words. The button becomes **Stop recording** and the Draft position becomes **Cancel**. Speech pauses/final segments do not submit anything. Stop recording flushes the last words and waits for a complete final transcript before sending it with the current candidate to the authenticated correction backend. Unexpected end, incomplete text or errors retain the visible text/candidate without analysis; Cancel aborts capture or analysis. Final recognized text stays available with the result until retake/hide/exit; it is not logged or saved locally. No expense or draft is saved by voice editing. This branch declares `RECORD_AUDIO`; unsupported runtimes can continue editing on the website.

Deploy both sides together. Flow Ledger 2 must migrate through `0015_device_expense_grants` and deploy the matching website/API before installing this package. Set `APP_BASE_URL=https://ledger.zcorw.xyz` and configure backend recognition. An older backend cannot serve the new review workflow. See [new workflow](docs/REVIEW-WORKFLOW.md), [agent flow](docs/AGENT-FLOW.md), [API contract](docs/OCR-CONTRACT.md) and [device acceptance](docs/DEVICE-ACCEPTANCE.md).

Temple swipes select only the bottom actions; head movement selects the seven fields in their displayed rows and columns (merchant; amount/category; date/currency; account/note). Each area remembers its own focus. The first swipe from a field restores the previous action without advancing it; the first head motion from the actions restores the previous field without moving it. Further inputs navigate within that area, with field edges clamped and no row wrap. Click/Enter edits the current field. The [official orientation sensor](https://open.rokid.com/aiui/api/device/absolute-orientation-sensor?lang=en-US&version=0.19.0) supplies relative pose readings: after 250ms at a quiet pose, a deliberate 12-degree tilt/turn held for 120ms moves once, and a 150ms return to the 5-degree neutral band rearms it. Holding a turn does not repeat; small, brief or diagonal motions are ignored. Sensor availability, mounting-axis direction and thresholds require real-glasses acceptance; unsupported hosts show a message while buttons remain usable. Sensing stops during hidden/unloaded, whole-bill speech and locked financial states. The field voice view keeps the current value, live text and every legal choice in four columns; twelve categories fit compact cards, and head Up/Down scrolls longer lists in the same page. Swipes choose Stop/Retry or Cancel, Enter activates, and Back cancels. Editing or canceling returns to the remembered field without overwriting the remembered bottom action. Ambiguous speech keeps the choices and original value. Account ID/name form one logical field; the Voice edit button retains whole-bill correction.

The paired backend adds `GET /review-options` (version 1; complete categories, enabled currencies and active owned accounts) and optional `targetField` on `POST /review-correction`. Scoped replies add `fieldOutcome`: `matched`, `unchanged`, `ambiguous` or `unmatched`. Client/server both enforce the field boundary. Enumerated fields use exact normalized labels/aliases, unique contained names, then conservative text similarity (at least 0.72 with a 0.15 lead); close competitors/negations require clarification. This is not general phonetic/semantic matching. Free fields use the existing model with an explicit target; other returned fields are discarded. There are no financial writes. Choices stay in memory and clear on hide/exit. Deploy this backend increment before installing the native package; unavailable/invalid choices fail explicitly. Existing requests without a target retain their earlier behavior.

Voice results name changed fields and show the full resulting merchant when it changes. If a complete merchant-only instruction exactly matches the existing name and there are no warnings, the result says “商户已是 SEIYU，无需修改”. Other unchanged results ask the user to check the recognized text, display the current merchant and retain server warnings; an empty change list alone is not treated as proof that the instruction matched.

## Local checks

Use Node.js 22 or newer: `npm run check` and `npm test`. Install development dependencies with `npm ci --ignore-scripts`. Tests use synthetic photos/responses and never contact production recognition. Compile and sync the resource package in a supported native AIUI runtime for device acceptance.

Run `node qa/review-layout.mjs` to check the actual native template at 448×150, 480×168, 320×240, 480×320 and 640×360. Below 200px tall, compact spacing/fonts keep all review fields and actions visible; the 480×168 cloud card observed during release preflight is included. During voice capture/analysis, a transcript panel occupies the field area with reachable Stop/Cancel controls. `REVIEW_CHROMIUM_PATH` selects an installed Chromium browser; `REVIEW_SCREENSHOT_DIR` saves synthetic previews. The 130 geometry cases also run in CI and cover empty/long values, first/final merchant glyph bounds (Latin, CJK and mixed names), scrolling, unchanged-result feedback, authorization feedback and manual voice states. A local AIX does not update the cloud Agent or the glasses. Import/rebuild it in the existing cloud Agent, then update the phone/glasses resource package and record the actual installed version before acceptance.

The [receipt review demo](docs/REVIEW-PROTOTYPE.md) retains individual-field editing and explicit confirmation. `/preview/chain.html` composes a complete synthetic capture, recognition, edit and submission sequence. These demos are not registered native routes and do not contact the camera or real backend. Only synthetic recovery data is stored in this browser; see [integration scope](docs/SYNTHETIC-CHAIN.md).
